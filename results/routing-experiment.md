# Technical-vs-general tokenizer router (Story 2.4)

Generated by `scripts/routing_experiment.py` on 1012 FLORES-pl prose + 500 code docs. Total tokens to encode the whole prose+code eval set under each strategy (lower is better); three 32k BPE tokenizers (general=Polish prose, technical=code, mixed=both).

| Strategy | Total tokens |
|----------|-------------:|
| general-only | 342,435 |
| technical-only | 279,562 |
| mixed-only | 242,099 |
| **routed** | **269,605** |

Router accuracy (prose vs code): **88.2%**. Routing uses **11.4% more** tokens than the mixed single tokenizer - the mixed tokenizer wins.

## Decision: DROP

Criterion: keep routing only if it beats a single tokenizer trained on the mixed corpus by >=5% with an accurate router (>=95%). It does not: a single tokenizer trained on the mixed corpus is both simpler and more efficient. It allocates vocab across both domains and handles their overlap (English identifiers in code, symbols in prose), whereas two hard-switched specialists each waste vocab and the router mis-routes some inputs. Prefer one mixed-domain tokenizer over a technical/general router.
